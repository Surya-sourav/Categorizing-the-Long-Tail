# longtail-txcat

Code, data pipeline and frozen caches for

> **Categorizing the Long Tail: An Empirical Study of Web-Search-Augmented Fallback for
> Embedding-Based Transaction Classification.** Surya Parida, Independent Researcher.

The question: embedding + kNN classifiers for card transactions are near-perfect on merchants they
have seen before and collapse on the long tail of merchants they have not. Does routing low-confidence
retrievals to an LLM fed with web-search evidence fix the tail, at what cost, and does writing the
resolved merchants back into the index let the system heal itself over a stream?

## Evidence stack

| Role | Dataset | What it is | Use |
|---|---|---|---|
| Primary (real) | Washington DC Purchase Card Transactions, 2019 to present | Real acquirer descriptors (`STAPLES       00102186`, `WW GRAINGER 912`) with MCC labels and real dates, from the DC open-data ArcGIS layer | All headline numbers |
| Second real | Oklahoma State PCard FY2023 to FY2025 | Monthly CSVs from data.ok.gov | Cross-dataset cold-start: index built from DC, tested on merchants that never appear in DC |
| Instrument | Own generator | Real brand names from the OSM name-suggestion-index (pinned 8.0.20260729), templated statement noise, Zipf frequencies with a tunable exponent | Tail-severity sweep only |
| Sanity | DoDataThings/us-bank-transaction-categories-v2 | Template-generated | Internal check, no paper numbers |

Split is temporal, never random: DC train 2019-01-01 to 2023-12-31 (189,581 rows, 17,166 merchants),
test 2024-01-01 onward (90,466 rows, 10,443 merchants). Tail = merchant frequency <= 3 in the training
index (sensitivity at <= 2 and <= 5). Exp 0 verifies a volume rule (>= 20k test rows, >= 2,500 tail
merchants) and writes the chosen window to `results/window_decision.json`.

## Labels

MCC descriptions from both sources are mapped to 15 macro categories through two committed files in
`data/taxonomy/`: `mcc_to_category.csv` (981 MCCs, generated by `scripts/build_taxonomy.py` from
inspectable range rules and overrides, then reviewed) and `mcc_description_aliases.csv` (each observed
description string to an MCC: exact, fuzzy, or one of 200 hand-written `manual_aliases.csv` entries
for abbreviated text and hotel/airline brand descriptions). Ambiguous "not elsewhere classified" codes
(5999, 5399, 7399, 8999) are flagged, excluded from headline tables and reported as their own slice.
A 300-row label-noise audit of DC (judged by the author, `label_noise_audit_sample.csv`) found 4.4%
clearly wrong labels and 16% unclear; see `results/tables/tab0_label_noise.csv`.

## Privacy

Only the normalized merchant string ever leaves the machine. Loaders drop cardholder names, amounts,
item descriptions and agency at the boundary (`src/txcat/data/schema.py` enforces exactly five columns),
the DC download never requests those fields, and the search and LLM clients accept a merchant string
only. Raw and processed data are never committed; `data/download.py` fetches them.

## Setup

```bash
curl -LsSf https://astral.sh/uv/install.sh | sh
uv venv --python 3.12 .venv && uv pip install -e ".[dev]"
cp .env.example .env   # OPENAI_API_KEY, FIRECRAWL_API_KEY, NVIDIA_API_KEY (only for live cache passes)
.venv/bin/pytest       # unit tests, no network
```

## Data

```bash
.venv/bin/python data/download.py mcc_codes dc oklahoma
```

DC is paged from the ArcGIS layer (1,000 rows per page, resumable, verified against the layer's row
count); Oklahoma is 36 monthly CSVs. The generator vocabulary (`data/processed/gen_vocab.parquet`,
2,663 US brands) is committed because it is derived from public OSM data.

## Reproduce from cache (no API calls)

```bash
.venv/bin/python reproduce.py --config configs/dc.yaml --seeds 42 43 44
```

Runs Exp 0 to 3 in reproduce mode from the committed caches under `cache/` (web search JSON, LLM JSON,
float16 embeddings), refuses to run if a prompt differs from `prompts/PROMPT_HASHES.json`, and writes a
manifest (model ids, prompt hashes, HNSW parameters, git commit, host, package versions) to
`results/logs/`.

## Re-running the live cache pass

```bash
.venv/bin/python -m experiments.pilot --config configs/dc.yaml --n 100        # ~$1, freezes prompts
.venv/bin/python -m experiments.exp2_cache_pass --config configs/dc.yaml       # ~$20, resumable
```

Every live client records estimated spend in `cache/spend_ledger.json` and raises before crossing
`budget.max_usd` (default 40). Prompts are frozen after the pilot; the LLM cache is keyed on the
prompt hash, so an edited prompt is a new file, not an overwrite.

## Experiments

| # | Script | Output |
|---|---|---|
| 0 | `experiments/exp0_data_audit.py` | dataset stats, taxonomy coverage, window decision, label-noise audit sample |
| 1 | `exp1_tail_characterization.py`, `exp1_generator_sweep.py` | Zipf fit, accuracy by frequency bin, accuracy vs similarity, alpha sweep |
| 2 | `exp2_cache_pass.py` (live), `exp2_fallback_comparison.py` (offline) | main table, with-web vs no-web paired bootstrap, accuracy-cost frontier, prompt sensitivity, agentic-search ablation, Oklahoma cold-start |
| 3 | `exp3_streaming_convergence.py` | fallback decay, cumulative cost and F1 under never / always / confidence-gated write-back |
| 4 | `exp4_failure_taxonomy.py` | failure sample template and taxonomy table |
| 5 | `exp5_backbone_comparison.py` | five embedding backbones |

## Layout

```
src/txcat/            normalizer, embedder (cached), index (hnswlib), gate, web_search, llm_fallback,
                      writeback, stream, metrics, baselines, budget, manifest, generator/, data/
experiments/          one script per experiment; -m experiments.<name>
analysis/             matplotlib style and figure functions
prompts/              frozen prompt templates, PROMPT_HASHES.json, model_versions.json
cache/                committed API caches (web_search/, llm/, embeddings/)
data/taxonomy/        committed MCC mapping, aliases, audit sample
results/              tables/, figures/, fes/, logs/, window_decision.json
docs/superpowers/     design spec and implementation plans
```

Models pinned in `prompts/model_versions.json`. Embeddings: all-MiniLM-L6-v2, bge-small-en-v1.5,
all-mpnet-base-v2, FinBERT (mean-pooled, as an encoder), text-embedding-3-small. Fallback LLMs:
gpt-5-nano, gpt-5-mini, and two open-weight models on NVIDIA's free NIM endpoint (Gemma 4 31B IT,
Nemotron 3.5 Lightning 30B-A3B). Web evidence: Firecrawl search API (Tavily and Brave also implemented);
OpenAI built-in web search appears only in a 300-merchant ablation.
